# PolicyForge

PolicyForge, a policy issuance and lifecycle management platform for Horizon Insurance covering Term Life,
Motor and Household: quote, application, underwriting, issuance, endorsement, renewal and cancellation,
with versioned policy rule sets.

Business case: `docs/business-case.md` · Root spec: `specs/app_spec.md` · Full index: `AGENTS.md`
**Canonical names, paths, models, tables and rule-file shape: `docs/conventions.md` — use them verbatim.**

## Non-Negotiable Project Rules

1. **No hand-coding.** Production code, tests and migrations are generated by Claude Code agents only.
   Humans edit substrate only: specs, CLAUDE.md files, agents, skills, commands, hooks, docs.
2. **Spec is truth.** When spec and code disagree the spec wins — update the spec deliberately, then regenerate.
3. **PR-only merges.** Never commit to `main`; work on `<type>/<description>` branches, merge with `git merge --no-ff`.
4. **Synthetic data only.** Seeds and fixtures are dummy values — no real Aadhaar, PAN or health data.

## Domain Invariants (enforced by project hooks + architecture tests)

- Money (premium, refund, sum insured) is `decimal.Decimal`, quantized to 0.01 `ROUND_HALF_UP` — never `float` (NFR-01, hook `premium-precision-check`).
- Policy versions, endorsements, state transitions, refunds, audit rows and migrations are append-only (NFR-02/05, hooks `policy-immutability-check`, `append-only-repository-check`, `shell-immutability-check`).
- Aadhaar, PAN and health declarations never reach logs — use the redacting logger in `backend/src/lib/` (NFR-03, hook `pii-redaction-check`).
- Auth is enforced at the API layer; underwriter/admin actions are audited with actor ID (NFR-04).
- Premiums come only from the active versioned rule file `backend/policy_rules/<product>/v<N>.json` (AC-01).
- Invalid policy state transitions raise `InvalidPolicyStateException` (AC-10).
- Every `AC-NN` in `specs/` has ≥1 test named `test_acNN_*` with `@pytest.mark.ac("AC-NN")` (check with `/ac-coverage`).

**Full stack:** Start backend + frontend (see init.sh)

## Architecture

Strict layered architecture: Types → Domain → Config → Repository → Service → API → UI.
One-way dependencies only (`backend/src/<layer>/`, imports as `from src.<layer> ...`).
See `.claude/architecture.md`, `docs/architecture.md`; enforced by import-linter + `backend/tests/architecture/`.
