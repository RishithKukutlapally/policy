# specs/ — the source of truth

| Path | Produced by |
|------|-------------|
| `app_spec.md` | Root spec — scope, products, cross-cutting NFRs, AC index |
| `<feature>_spec.md` | product-catalog, quote-engine, underwriting, policy-issuance, endorsement, renewal-cancellation |
| `brd/` | `/brd` interview output |
| `stories/` | `/spec` — epics, stories, dependency graph |
| `design/` | `/design` — system design, API contracts, data models, mockups |
| `reviews/` | evaluator / security / clean-code / AC-coverage reports |
| `test_artefacts/` | test plans and fixtures from `/test` |

## Rules

- Every feature spec has an `## Acceptance Criteria` section with `AC-NN` ids **and** Given-When-Then scenarios.
- AC ids are global and stable (AC-01 … AC-10 from the brief; new ones continue at AC-11). Never renumber.
- Spec is truth: change the spec first (commit `docs(spec): …`), then regenerate code and tests.
- `specs/reviews/evaluator-report.md` must end with `VERDICT: PASS` before a sprint merges (sprint-contract-gate hook).
- **Authoritative AC traceability report:** `specs/reviews/ac-audit.md`, generated by
  `uv run scripts/ac_audit_agent.py` (counts the `@pytest.mark.ac("AC-NN")` marker — decorator or
  module-level `pytestmark` — and `AC-NN` in Playwright test titles; its last line is the verdict, and it
  exits non-zero when any AC has no test). `/ac-coverage` is the interactive equivalent of the same check.
