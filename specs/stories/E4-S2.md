# E4-S2 — Application submit → decide: `Application` + `UnderwritingDecision`

- **ID:** E4-S2
- **Epic:** E4 — Application & underwriting
- **Layer:** Service
- **Group:** S2-C
- **Sprint:** 2
- **Depends on:** E4-S1, E3-S2
- **Traces:** AC-03, AC-04, NFR-02, NFR-03

## Description

`src/service/application_service.py` turns a quote into an application: it validates KYC stub + risk inputs,
moves the `Application` through `SUBMITTED → UNDERWRITING → AUTO_BIND | MANUAL_REVIEW | DECLINED`, and appends an
`UnderwritingDecision` (`decided_by = "SYSTEM"`) computed on the product's active version. A thin router
`src/api/routers/applications.py` exposes `POST /api/applications` and `GET /api/applications/{application_id}`
for `CUSTOMER`. Only masked Aadhaar/PAN are stored; PII never reaches logs.

## Acceptance Criteria

1. [AC-03] `POST /api/applications` as CUSTOMER with `{quote_id, kyc: {full_name, date_of_birth, aadhaar: "999900000001", pan: "AAAAA0001A", address}}` for the golden MOTOR quote returns 201 `{application_id, status: "AUTO_BIND", decision: "AUTO_BIND", reason_codes: [], rule_version: 1}` _(category: integration)_
   - Verify: create the golden MOTOR quote; POST the application; assert 201 and body fields; GET `/api/applications/{id}` and assert the same status
2. [AC-03] Invalid KYC/risk input returns 422 `VALIDATION_ERROR` with `details` (e.g. `{field: "kyc.pan", code: "INVALID_FORMAT"}`) and creates no `applications` or `underwriting_decisions` rows; an unknown `quote_id` returns 404 `NOT_FOUND` _(category: integration)_
   - Verify: POST with pan `ABC123` and assert 422 plus unchanged row counts; POST with a random UUID quote_id and assert 404
3. [AC-04] A MOTOR quote with vehicle_age_years 12 yields application status `MANUAL_REVIEW` and one `underwriting_decisions` row `{decision: "MANUAL_REVIEW", reason_codes: ["MO-UW-002"], product: "MOTOR", rule_version: 1, decided_by: "SYSTEM"}`; vehicle_age_years 16 yields status `DECLINED` with reason code `MO-UW-001` _(category: functional)_
   - Verify: submit both applications through the service; query `underwriting_decisions` by application id; assert the exact decision, reason codes and rule version
4. [AC-03] The application records the status path in order: `SUBMITTED`, `UNDERWRITING`, then the decision status — visible as `status_history` on `GET /api/applications/{id}` _(category: functional)_
   - Verify: submit an AUTO_BIND application; GET it; assert `status_history == ["SUBMITTED", "UNDERWRITING", "AUTO_BIND"]`
5. [—] `underwriting_decisions` is append-only (new Alembic revision; repository exposes `add` + reads only) and `applications` stores only `aadhaar_masked = "XXXX-XXXX-0001"` and `pan_masked = "XXXXX0001X"`, never the raw values _(category: security)_
   - Verify: introspect `UnderwritingDecisionRepository` public methods; submit an application and `SELECT *` from `applications`; assert `999900000001` and `AAAAA0001A` appear in no column
6. [—] No log line emitted during a submission contains the raw Aadhaar, PAN or any health-declaration value (TERM_LIFE with `health_declaration: {has_pre_existing_condition: true, details: "asthma"}`) _(category: security)_
   - Verify: capture all log output while submitting the TERM_LIFE application; assert `999900000001`, `AAAAA0001A` and `asthma` are absent; assert log lines include the `application_id`
