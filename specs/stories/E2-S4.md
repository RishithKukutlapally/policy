# E2-S4 — Catalog API + Product Catalog Manager UI

- **ID:** E2-S4
- **Epic:** E2 — Product catalog & rule versions
- **Layer:** UI
- **Group:** S1-E
- **Sprint:** 1
- **Depends on:** E2-S3, E1-S5
- **Traces:** AC-11, AC-02, AC-22, AC-24

## Description

Expose the catalog service in `src/api/routers/products.py` and build the admin "Product Catalog Manager"
screen at `/admin/catalog`. Admins see the three products, each product's versions with text status badges,
can create a draft by pasting rule-set JSON and publish it. Read endpoints are open to every role; write
endpoints require `ADMIN`.

## Acceptance Criteria

1. [AC-02] `GET /api/products` with any valid role returns 200 and a JSON array of three objects `{product, name, active_version, currency}` for `TERM_LIFE`, `MOTOR`, `HOUSEHOLD` (order `TERM_LIFE`, `MOTOR`, `HOUSEHOLD`; `active_version` is `null` with no PUBLISHED version); `GET /api/products/MOTOR/versions` returns 200 with each version's `version`, `status` and `is_active` _(category: integration)_
   - Verify: call both endpoints as `CUSTOMER`; assert 200 and the three products in order with `active_version` 1, `currency` `INR` and a non-empty `name`; assert MOTOR versions list contains v1 `PUBLISHED`, `is_active: true`
2. [AC-11] `POST /api/products/MOTOR/versions` as ADMIN with a valid rule JSON returns 201 `{product: "MOTOR", version: 2, status: "DRAFT"}`; `POST /api/products/MOTOR/versions/2/publish` returns 200 with `status: "PUBLISHED"`; publishing it again returns 409 `VERSION_IMMUTABLE`; an invalid body returns 422 `VALIDATION_ERROR` whose `error.details` names the failing path _(category: integration)_
   - Verify: POST a valid draft and assert 201 body; POST publish and assert 200; POST publish again and assert 409 with `error.code` `VERSION_IMMUTABLE`; POST a draft with numeric `base_rate` and assert 422 whose `error.details[].field` contains `premium.base_rate`
3. [AC-22] The write endpoints return 401 `UNAUTHENTICATED` without actor headers and 403 `FORBIDDEN` for `CUSTOMER` or `UNDERWRITER` _(category: security)_
   - Verify: POST a draft with no headers and assert 401; POST as `X-Actor-Role: UNDERWRITER` and assert 403; POST publish as `CUSTOMER` and assert 403
4. [AC-11] In the UI as Admin, `/admin/catalog` lists the three products; selecting MOTOR shows a versions table with text badges "PUBLISHED"/"DRAFT" and "Active" on the active row; a "Publish" button appears only on DRAFT rows, and clicking it (with a confirm dialog) turns the row's badge to "PUBLISHED" and "Active" _(category: ui)_
   - Verify: Playwright as Admin creates a v2 draft via the "New draft" form; assert the v2 row shows "DRAFT" and a Publish button while v1 has none; click Publish and confirm; assert v2 shows "PUBLISHED" and "Active"
5. [AC-24] The catalog screen is usable at 390 px: the versions table renders as stacked cards each showing version, status badge and action, with no horizontal scroll _(category: ui)_
   - Verify: Playwright at 390×844 opens `/admin/catalog` as Admin; assert version cards are visible with status text; assert `scrollWidth ≤ 390`
