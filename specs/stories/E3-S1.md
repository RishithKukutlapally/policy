## Description

`src/domain/premium_calculator.py` is a pure function `calculate_premium(rule_set, inputs) -> Decimal` with no I/O,
logging or clock. Formulas (intermediates unrounded, final result `max(minimum_premium, raw)` quantized to 0.01
`ROUND_HALF_UP`): TERM_LIFE `SI × base_rate × age_mult × term_mult × (1 + smoker_loading if smoker)`; MOTOR
`SI × base_rate × vehicle_age_mult × engine_cc_mult × zone_rate × (1 − ncb_discount)`; HOUSEHOLD
`SI × base_rate × construction_rate × (1 + flood_zone_loading if in_flood_zone) × (1 − security_discount if has_security_system)`.
Golden values below use the v1 files from E2-S1; input field names follow `docs/conventions.md` (MOTOR `owner_age`, `ncb_percent` as a string key).

## Acceptance Criteria

1. [AC-01] MOTOR golden: sum_insured `500000.00`, vehicle_age_years 3, engine_cc 1200, zone `A`, ncb_percent `"20"` → premium `Decimal("14322.00")`; minimum-premium case sum_insured `100000.00`, vehicle_age_years 2, engine_cc 900, zone `B`, ncb_percent `"50"` (raw 1550.00) → `Decimal("2500.00")` _(category: functional)_
   - Verify: load `motor/v1.json` into a `RuleSet`; call `calculate_premium` with each input; assert exact Decimal equality with the golden values
2. [AC-01] TERM_LIFE golden: age 35, sum_insured `5000000.00`, term_years 20, smoker false → `Decimal("9900.00")`; same with smoker true → `Decimal("14850.00")` _(category: functional)_
   - Verify: load `term_life/v1.json`; calculate both inputs; assert exact Decimal equality
3. [AC-01] HOUSEHOLD golden: sum_insured `3000000.00`, construction_type `BRICK`, in_flood_zone true, has_security_system true → `Decimal("2700.00")`; ROUND_HALF_UP case sum_insured `3000625.00`, `BRICK`, in_flood_zone true, has_security_system false (raw 3000.625) → `Decimal("3000.63")` (banker's rounding would give 3000.62) _(category: functional)_
   - Verify: load `household/v1.json`; calculate both inputs; assert `2700.00` and `3000.63` exactly and that the result exponent is -2
4. [AC-01] Determinism: 1000 repeated calls with the same rule set and input return identical Decimals, and non-final intermediates are not rounded (MOTOR sum_insured `123457.00`, vehicle_age_years 3, engine_cc 1200, zone `A`, ncb_percent `"20"` → `Decimal("3536.30")`) _(category: functional)_
   - Verify: loop 1000 calls and assert a single distinct result; compute the 123457.00 case and assert `3536.30`
5. [AC-01] Inputs outside every configured band (e.g. MOTOR engine_cc 100000, unknown zone `Z`, ncb_percent `"30"`) raise `PremiumFactorNotFoundError` naming the factor, rather than defaulting _(category: functional)_
   - Verify: call with each invalid input; assert `PremiumFactorNotFoundError` whose message contains `engine_cc_bands`, `zone_rates` and `ncb_discounts` respectively
6. [—] `premium_calculator.py` contains no `float` usage, returns `Decimal` for every product, and imports only `decimal`, `dataclasses`/`typing` and `src.types` _(category: security)_
   - Verify: run `test_no_float_in_money_code` and `test_domain_purity` and assert pass; assert `isinstance(result, Decimal)` for the three golden cases
