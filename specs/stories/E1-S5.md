# E1-S5 — Frontend shell: routing, role switcher, responsive layout

- **ID:** E1-S5
- **Epic:** E1 — Platform foundation
- **Layer:** UI
- **Group:** S1-C
- **Sprint:** 1
- **Depends on:** E1-S3
- **Traces:** AC-24, AC-22

## Description

Build the React + Vite + TypeScript shell that all screens plug into: a router, a typed API client that attaches
the auth-stub headers, a header role switcher for the three demo users, and a responsive layout with a side
nav that collapses on mobile. Navigation items depend on the selected role.

## Acceptance Criteria

1. [AC-24] At a 1280 px viewport the side navigation is visible; at 390 px it is hidden behind a button with accessible name "Open navigation", which toggles it open, and `document.documentElement.scrollWidth` is ≤ 390 (no horizontal scroll) _(category: ui)_
   - Verify: Playwright at 1280×800 asserts the nav landmark is visible; at 390×844 assert the nav is hidden and the "Open navigation" button is visible; click it and assert the nav becomes visible; evaluate scrollWidth and assert ≤ 390
2. [—] The header role switcher offers exactly three demo users — `Customer (cust-001)`, `Underwriter (uw-001)`, `Admin (admin-001)` — and the selection persists across a page reload _(category: ui)_
   - Verify: render the shell; open the switcher and assert the three labelled options; select Admin, reload, and assert Admin is still selected
3. [AC-22] Every request made through the API client carries `X-Actor-Id` and `X-Actor-Role` matching the selected demo user, plus an `X-Correlation-ID` UUID _(category: integration)_
   - Verify: vitest with a mocked fetch; select Underwriter and call the client; assert headers `X-Actor-Id: uw-001`, `X-Actor-Role: UNDERWRITER` and a UUID-formatted `X-Correlation-ID`
4. [—] Navigation is role-based: CUSTOMER sees "Get a Quote" and "My Policies"; UNDERWRITER sees "Workbench"; ADMIN sees "Product Catalog", "Underwriting Review", "Portfolio" — and an unknown route renders a "Page not found" view _(category: ui)_
   - Verify: for each role, render the shell and assert the exact nav link names; navigate to `/no-such-page` and assert the heading "Page not found"
5. [—] Accessibility basics: every nav link and the role switcher have accessible names, all are reachable with the Tab key in DOM order, and focused elements show a visible focus outline _(category: ui)_
   - Verify: run axe via Playwright on the shell at 1280 px and assert zero serious/critical violations; press Tab repeatedly and assert focus reaches the role switcher and each nav link
