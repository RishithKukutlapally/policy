## Description

Define the product rule set as data: enums in `src/types/enums.py`, immutable value objects (`RuleSet` and
children) in `src/types/rules.py`, the JSON Schema `backend/policy_rules/schema/rule-file.schema.json`, and the
three published v1 files `term_life/v1.json`, `motor/v1.json`, `household/v1.json` with their SHA-256 lines in
`PUBLISHED.lock`. The v1 values below are the golden inputs for the quote engine (E3-S1) and underwriting
(E4-S1) and the single source of every money example in `specs/`. Underwriting `when` conditions use the
`docs/conventions.md` format — `<field> <op> <value>` clauses joined by ` and ` (ops `<`, `<=`, `>`, `>=`, `==`,
`!=`, `in`) over quote input fields plus the derived `age_at_term_end` (= `age + term_years`) and
`has_pre_existing_condition` — a documented assumption, not a general DSL.

v1 factor values: TERM_LIFE `age_bands` 18–30 `1.00`, 31–40 `1.20`, 41–50 `1.60`, 51–60 `2.20`;
`term_years_bands` 5–15 `1.00`, 16–25 `1.10`, 26–30 `1.25`; `smoker_loading` `"0.50"`. MOTOR `vehicle_age_bands`
0–5 `1.00`, 6–10 `1.15`, 11–15 `1.35`, 16–99 `1.60`; `engine_cc_bands` 0–1000 `1.00`, 1001–1500 `1.10`,
1501–99999 `1.25`; `ncb_discounts` `{"0":"0.00","20":"0.20","25":"0.25","35":"0.35","45":"0.45","50":"0.50"}`;
`zone_rates` `{"A":"1.05","B":"1.00"}`. HOUSEHOLD `construction_type_rates`
`{"CONCRETE":"0.90","BRICK":"1.00","TIMBER":"1.30","THATCH":"1.80"}`; `flood_zone_loading` `"0.25"`;
`security_discount` `"0.10"`. Loadings (`smoker_loading`, `flood_zone_loading`) are added to 1 and discounts
(`ncb_discounts`, `security_discount`) are subtracted from 1 (formulas in `docs/conventions.md`). Eligibility age
fields: TERM_LIFE `age`, MOTOR `owner_age`, HOUSEHOLD `proposer_age`. Every product also carries the manual codes
`<P>-UW-900` "Underwriter approved", `<P>-UW-901` "Admin override: risk accepted" and `<P>-UW-902` "Underwriter
declined" (`<P>` = `TL`/`MO`/`HH`), used only by underwriter decisions and admin overrides.

## Acceptance Criteria

1. [AC-02] `ProductCode` has exactly `TERM_LIFE`, `MOTOR`, `HOUSEHOLD`, and one v1 file exists per product under its lower-snake-case folder, each with `"status": "PUBLISHED"`, `"version": 1`, `"currency": "INR"`, `"effective_from": "2026-01-01"` _(category: functional)_
   - Verify: assert `[p.value for p in ProductCode] == ["TERM_LIFE", "MOTOR", "HOUSEHOLD"]`; load each of the three files; assert the four field values
2. [AC-02] The three rule sets are distinct and carry the product-specific factor keys and values above: TERM_LIFE `age_bands`, `smoker_loading`, `term_years_bands` (base_rate `"0.0015"`, minimum_premium `"3000.00"`); MOTOR `vehicle_age_bands`, `engine_cc_bands`, `ncb_discounts`, `zone_rates` (base_rate `"0.0310"`, minimum_premium `"2500.00"`); HOUSEHOLD `construction_type_rates`, `flood_zone_loading`, `security_discount` (base_rate `"0.0008"`, minimum_premium `"1500.00"`) _(category: functional)_
   - Verify: load each file; assert the exact `premium.factors` key set and band/map values per product; assert the base_rate and minimum_premium strings; assert no two files have equal `premium` objects
3. [AC-02] Every v1 file validates against `rule-file.schema.json`; the schema rejects a file with a numeric (non-string) money/rate value such as `"base_rate": 0.031`, a missing `underwriting.reason_codes`, a `reason_code` not matching `^(TL|MO|HH)-UW-\d{3}$`, or a `cancellation.method` other than `PRO_RATA` _(category: functional)_
   - Verify: validate the three files with `jsonschema` and assert no errors; validate four mutated copies (one per defect); assert each raises a `ValidationError` naming the offending path
4. [—] v1 underwriting rules and eligibility are: TERM_LIFE age 18–60, sum insured 500000.00–50000000.00, `TL-UW-001` `age_at_term_end > 75` → DECLINE, `TL-UW-002` `sum_insured > 10000000` → MANUAL_REVIEW, `TL-UW-003` `has_pre_existing_condition == true` → MANUAL_REVIEW; MOTOR owner_age 18–75, sum insured 100000.00–5000000.00, `MO-UW-001` `vehicle_age_years > 15` → DECLINE, `MO-UW-002` `vehicle_age_years > 10` → MANUAL_REVIEW, `MO-UW-003` `sum_insured > 2500000` → MANUAL_REVIEW; HOUSEHOLD proposer_age 18–80, sum insured 500000.00–20000000.00, `HH-UW-001` `construction_type == THATCH` → DECLINE, `HH-UW-002` `in_flood_zone == true and sum_insured > 5000000` → MANUAL_REVIEW; each `reason_codes` map also holds `<P>-UW-900`, `<P>-UW-901`, `<P>-UW-902`; all products renewal 12 months (TERM_LIFE: annual premium), grace 30 days, free-look 15 days, admin fee `"250.00"` _(category: functional)_
   - Verify: load each file into `RuleSet`; assert eligibility bounds, each rule's `when` string, reason code and decision, and the renewal/cancellation values; assert every rule `reason_code` is a key of `reason_codes` and the three `-UW-90x` codes exist per product
5. [—] `RuleSet` value objects are frozen dataclasses whose money and rate fields are `decimal.Decimal` (never `float`); attempting attribute assignment raises `FrozenInstanceError` _(category: security)_
   - Verify: construct a `RuleSet` from `motor/v1.json`; assert `type(rs.premium.base_rate) is Decimal` and equals `Decimal("0.0310")`; assign `rs.version = 2` and assert `FrozenInstanceError`
6. [—] `PUBLISHED.lock` contains exactly three lines `<sha256>  term_life/v1.json`, `<sha256>  motor/v1.json`, `<sha256>  household/v1.json`, and `sha256sum -c PUBLISHED.lock` run from `backend/policy_rules/` reports all OK _(category: security)_
   - Verify: read the lock file and assert three lines with the relative paths; run `sha256sum -c PUBLISHED.lock` in that folder and assert exit code 0
