# E9-S4 — Playwright end-to-end journeys + snapshots at 1280 / 390 px

- **ID:** E9-S4
- **Epic:** E9 — Portfolio dashboard, seed & end-to-end
- **Layer:** UI
- **Group:** S4-F
- **Sprint:** 4
- **Depends on:** E9-S2, E8-S3, E7-S4, E6-S3, E4-S5
- **Traces:** AC-24, AC-01, AC-05, AC-06, AC-07, AC-08, AC-09, AC-14, AC-19, AC-20

## Description

Write the Playwright suite under `e2e/` that drives the full stack (started by `npm start` against the seed)
through the customer, underwriter and admin journeys using the header role switcher. Every test title contains
the `AC-NN` it proves so `/ac-coverage` can trace it, and visual snapshots for each key screen are committed at
desktop 1280 px and mobile 390 px. The suite runs in the GitLab CI `e2e` job.

## Acceptance Criteria

1. [AC-24] A Playwright config defines two projects, `desktop` (viewport 1280×800) and `mobile` (viewport 390×844), and `toHaveScreenshot` snapshots for Get a Quote, Apply, My Policies, Policy Detail, Endorse, Cancel, Underwriter Workbench, Product Catalog Manager and Portfolio Dashboard are committed under `e2e/` for both projects (18 baseline images) _(category: ui)_
   - Verify: run `npx playwright test --list` and assert both projects exist with the two viewports; list `e2e/**/*-snapshots/*.png` and assert 9 screens × 2 projects are committed; run `npx playwright test` and assert 0 snapshot diffs
2. [AC-01] Customer journey test titled `AC-01 AC-05 customer quotes, applies and is issued a MOTOR policy` gets a quote showing the premium and rule version, applies with synthetic KYC, receives `AUTO_BIND` and sees a new `MO-2026-######` policy with badge `ACTIVE` on My Policies _(category: integration)_
   - Verify: run that test in both projects; assert the quote premium text matches `₹\d{1,3}(,\d{2,3})*\.\d{2}` and equals the API quote; assert the policy row matches `MO-\d{4}-\d{6}` and shows `ACTIVE`
3. [AC-09] Underwriting journey test titled `AC-09 AC-14 underwriter decides and admin overrides a DECLINE` has the Underwriter approve a MANUAL_REVIEW case with a reason code, and the Admin override a DECLINE with a reason code and comment, after which the application shows `AUTO_BIND` and the audit trail lists both actor ids _(category: integration)_
   - Verify: run the test; assert the case leaves the queue after approval; assert after override the status text `AUTO_BIND` and two audit entries showing the underwriter and admin actor ids
4. [AC-06] Lifecycle tests titled `AC-06 customer endorses address`, `AC-07 admin end-of-day renews a paid policy and lapses an unpaid one` and `AC-08 AC-19 customer cancels with refund preview` each assert the resulting status badge (`ENDORSED`, `RENEWED`/`LAPSED`, `CANCELLED`) and the history or refund row on Policy Detail _(category: integration)_
   - Verify: run the three tests; assert each badge text and a new endorsement / transition / refund row; assert the cancel test's refund text equals the preview shown before confirmation
5. [AC-20] Test titled `AC-20 AC-24 admin portfolio dashboard at desktop and mobile` asserts the product cards, premium collected and renewal pipeline render, and at 390 px asserts `scrollWidth <= 390`, the side nav is collapsed behind a labelled menu button and tables render as stacked cards _(category: ui)_
   - Verify: run the test in both projects; on `mobile` assert the menu button with accessible name "Open navigation" is visible and the side nav hidden until clicked; assert no horizontal overflow
6. [—] Every `test(...)` title in `e2e/` contains at least one `AC-\d{2}` id, the suite passes in the CI `e2e` job in under 5 minutes, and `/ac-coverage` reports each AC above as covered by a Playwright test _(category: integration)_
   - Verify: grep all `test(` titles under `e2e/` and assert each matches `AC-\d{2}`; run the CI `e2e` job and assert success and duration < 5 min; run `/ac-coverage` and assert AC-01, AC-05…AC-09, AC-20, AC-24 list an e2e test
