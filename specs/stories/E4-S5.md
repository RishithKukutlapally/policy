# E4-S5 — Apply UI + Underwriter Workbench UI

- **ID:** E4-S5
- **Epic:** E4 — Application & underwriting
- **Layer:** UI
- **Group:** S2-F
- **Sprint:** 2
- **Depends on:** E4-S4, E1-S5
- **Traces:** AC-03, AC-04, AC-09, AC-14, AC-24, NFR-03

## Description

Build three screens on the Sprint 2 APIs: the customer "Apply" screen at `/apply/:quoteId` (KYC stub form, then
decision status + reason codes), the underwriter "Workbench" at `/underwriter/queue` (queue, case detail,
approve/decline with reason codes, audit trail), and the admin "Underwriting Review" at `/admin/underwriting`
(queue review + DECLINE override). PII is masked on screen and statuses are shown as text badges.

## Acceptance Criteria

1. [AC-03] As Customer, clicking "Apply" on the golden MOTOR quote opens `/apply/:quoteId` with labelled inputs Full name, Date of birth, Aadhaar, PAN, Address; submitting the synthetic values shows a status badge with text "AUTO_BIND"; submitting PAN `ABC123` shows an inline PAN error and no decision _(category: ui)_
   - Verify: Playwright creates the MOTOR quote, clicks Apply, fills the form and submits; assert badge text `AUTO_BIND`; repeat with PAN `ABC123` and assert the PAN field error
2. [AC-04] A MANUAL_REVIEW or DECLINED result shows each reason code with its description from the rule set (e.g. "MO-UW-002 — " followed by the v1 description) and "Rule version v1" _(category: ui)_
   - Verify: Playwright applies with a vehicle_age_years 12 quote; assert badge `MANUAL_REVIEW`, the text `MO-UW-002` and `Rule version v1`
3. [AC-14] As Underwriter, the Workbench lists MANUAL_REVIEW cases; opening one shows masked Aadhaar `XXXX-XXXX-0001`, reason codes and an audit trail; choosing reason code `MO-UW-900`, entering a comment and clicking "Approve" removes the case from the queue and the audit trail shows `UW_APPROVE by uw-001` _(category: ui)_
   - Verify: seed a MANUAL_REVIEW MOTOR case; Playwright as Underwriter opens it and approves; assert the queue no longer lists it and the case audit trail contains `UW_APPROVE` and `uw-001`
4. [AC-09] As Admin, `/admin/underwriting` lists DECLINED cases with an "Override" action; the override dialog requires a reason code and a comment of ≥ 10 characters (submit disabled otherwise); a successful override changes the badge to "AUTO_BIND" _(category: ui)_
   - Verify: seed a DECLINED MOTOR case; Playwright as Admin opens Override and asserts submit is disabled with comment `ok`; enter a valid comment and reason, submit, and assert badge `AUTO_BIND`
5. [—] No screen ever renders a raw Aadhaar or PAN: after the Apply → Workbench → Admin flow, the page text of every visited route contains neither `999900000001` nor `AAAAA0001A` _(category: security)_
   - Verify: Playwright collects `document.body.innerText` on each route visited in the flow; assert neither raw value appears; assert `XXXX-XXXX-0001` appears on the case detail
6. [AC-24] Apply, Workbench and Underwriting Review are usable at 390 px: queues render as stacked cards and dialogs fit the viewport with no horizontal scroll _(category: ui)_
   - Verify: Playwright at 390×844 opens each of the three routes; assert cards are visible and `scrollWidth ≤ 390`; open the override dialog and assert it is fully within the viewport
