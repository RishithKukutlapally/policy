# E1-S3 — Auth stub at controller layer + append-only `AuditRecord`

- **ID:** E1-S3
- **Epic:** E1 — Platform foundation
- **Layer:** API
- **Group:** S1-B
- **Sprint:** 1
- **Depends on:** E1-S1
- **Traces:** AC-22, NFR-02, NFR-04

## Description

Implement the documented role-header auth stub in `src/api/deps.py`: routers declare the roles they accept and
the dependency resolves an `Actor(actor_id, role)` from `X-Actor-Id` and `X-Actor-Role`
(`CUSTOMER` | `UNDERWRITER` | `ADMIN`). Add the `AuditRecord` model (`audit_records` table) and an append-only
`audit_record_repository.py` that services use to record every underwriter/admin action with the actor id.

## Acceptance Criteria

1. [AC-22] A role-protected route called without `X-Actor-Id` or without `X-Actor-Role` returns HTTP 401 with the error envelope `{"error": {"code": "UNAUTHENTICATED", "message": …, "details": null}}`; an `X-Actor-Role` value outside `CUSTOMER|UNDERWRITER|ADMIN` (e.g. `ROOT`) also returns 401 _(category: security)_
   - Verify: mount a test route requiring `ADMIN`; call it with no headers, with only `X-Actor-Id: admin-001`, and with `X-Actor-Role: ROOT`; assert 401 and `error.code == "UNAUTHENTICATED"` in all three cases
2. [AC-22] A route requiring `ADMIN` called with `X-Actor-Id: cust-001` and `X-Actor-Role: CUSTOMER` returns HTTP 403 with `error.code` `FORBIDDEN`; the same call with `X-Actor-Role: ADMIN` returns 200 and the handler receives `Actor(actor_id="cust-001", role=ActorRole.ADMIN)` _(category: security)_
   - Verify: call the test route as CUSTOMER and assert 403; call as ADMIN and assert 200; assert the handler echo contains the resolved actor id and role
3. [AC-22] Role checks live only at the API layer: no module under `src/service/` or `src/domain/` reads `X-Actor-Role` or imports `fastapi` _(category: security)_
   - Verify: grep `backend/src/service` and `backend/src/domain` for `X-Actor` and `fastapi`; assert zero matches
4. [—] Alembic revision creates `audit_records` with columns `id`, `actor_id` (not null), `actor_role` (not null), `action`, `entity_type`, `entity_id`, `detail` (JSON), `correlation_id`, `created_at`; `AuditRecordRepository.add(...)` inserts a row and `list_for_entity(entity_type, entity_id)` returns rows oldest first _(category: integration)_
   - Verify: run `alembic upgrade head` on a temp DB and inspect columns; add two records for entity `APPLICATION/app-1`; assert `list_for_entity` returns both in insertion order with the given `actor_id`
5. [—] `AuditRecordRepository` is append-only: it exposes no `update`, `delete`, `save` or `merge` method, and an attempted SQL `UPDATE` or `DELETE` on `audit_records` through the ORM session raises an error from a before-flush guard _(category: security)_
   - Verify: introspect the repository class and assert only `add` and read methods are public; load a record, mutate `action` and flush; assert an `AppendOnlyViolationError` is raised and the row is unchanged
