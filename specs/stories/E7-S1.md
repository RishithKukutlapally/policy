# E7-S1 — Renewal term + grace-period rules

- **ID:** E7-S1
- **Epic:** E7 — Renewal, lapse & payments
- **Layer:** Domain
- **Group:** S4-A
- **Sprint:** 4
- **Depends on:** E5-S1, E3-S1
- **Traces:** AC-07, NFR-01

## Description

Implement pure renewal rules in `src/domain/renewal_rules.py`. Given a policy's expiry date, the rule set's
`renewal.term_months` (12) and `renewal.grace_period_days` (30), whether the renewal premium is paid, and an
explicit `as_of` date, decide the `EndOfDayAction` `NONE`, `RENEW`, `IN_GRACE` or `LAPSE` (renewal premium due on
the new term's effective date = expiry + 1 day), and compute the next term's dates and refreshed premium from
the active rule version (inputs with ages and `vehicle_age_years` advanced by one term). The clock is always passed in, never read.

## Acceptance Criteria

1. [AC-07] For a policy with `expiry_date = 2027-01-14` the renewal due date is `2027-01-15` and the grace end is `2027-02-14` (due + 30 days); `renewal_action` returns `NONE` for `as_of = 2027-01-14`, `RENEW` for `as_of >= 2027-01-15` when paid, `IN_GRACE` for `2027-01-15 … 2027-02-14` when unpaid, and `LAPSE` for `as_of = 2027-02-15` when unpaid _(category: functional)_
   - Verify: parametrise `renewal_action(expiry, grace_days=30, paid, as_of)` over the listed dates and paid flags; assert each expected action; assert the boundary `2027-02-14` unpaid is `IN_GRACE` and `2027-02-15` unpaid is `LAPSE`
2. [AC-07] `next_term(expiry_date=2027-01-14, term_months=12)` returns `effective_date = 2027-01-15` and `expiry_date = 2028-01-14`; month-end dates clamp correctly (`expiry 2027-02-28` → next term `2027-03-01` to `2028-02-29`) _(category: functional)_
   - Verify: call `next_term` for both inputs and assert the returned dates; assert the function never calls `date.today()` (patching it to raise does not break the test)
3. [AC-07] The refreshed premium is computed by the E3-S1 premium calculator on the **currently active** rule version and returned with that version number: a MOTOR policy issued on v1 renewing when v2 is active returns `rule_version = 2` and the v2 premium _(category: functional)_
   - Verify: build v1 and v2 MOTOR `RuleSet` fixtures with different `base_rate`; call `renewal_premium(policy_inputs, active_rule_set=v2)`; assert the result equals `calculate_premium(v2, advanced_inputs)` (ages and vehicle_age_years + 1) and `rule_version == 2`
4. [—] The refreshed premium is a `Decimal` quantized to 0.01 `ROUND_HALF_UP` and not below the rule set's `premium.minimum_premium` (MOTOR `2500.00`) _(category: functional)_
   - Verify: assert the returned premium has exponent `-2` and type `Decimal`; use inputs that price below minimum and assert the result equals `Decimal("2500.00")`; run hook `premium-precision-check` on the module and assert no findings
5. [—] `renewal_action` only applies to policies in `ACTIVE` or `ENDORSED`; for `LAPSED`, `CANCELLED` or `RENEWED` it returns `NONE` without raising, so the end-of-day job can skip them _(category: functional)_
   - Verify: parametrise over the 3 terminal statuses with `as_of` past grace end and unpaid; assert `NONE` each time; assert `ENDORSED` behaves like `ACTIVE`
