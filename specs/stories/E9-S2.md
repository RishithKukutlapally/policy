# E9-S2 — Admin Portfolio Dashboard UI

- **ID:** E9-S2
- **Epic:** E9 — Portfolio dashboard, seed & end-to-end
- **Layer:** UI
- **Group:** S4-E
- **Sprint:** 4
- **Depends on:** E9-S1
- **Traces:** AC-20, AC-24

## Description

Build the admin **Portfolio Dashboard** screen at `/admin/portfolio` consuming `GET /api/admin/portfolio`.
It shows summary cards (active policies per product, premium collected, refunds paid), a renewal-pipeline
table and a lapse-forecast table, with an "As of" date selector. It is a clean functional internal tool with
text status labels and `en-IN` money formatting.

## Acceptance Criteria

1. [AC-20] As the Admin demo user, `/admin/portfolio` shows three product cards labelled `Term Life`, `Motor`, `Household` with their active-policy counts, plus cards "Premium collected" (e.g. `₹43,000.00`) and "Refunds paid" (e.g. `₹8,791.10`) matching the API response _(category: ui)_
   - Verify: in Playwright stub or seed the API data; open `/admin/portfolio`; assert the card texts and amounts equal the API values formatted `en-IN`
2. [AC-20] The "Renewal pipeline" table lists policy number, product, due date, renewal premium and a text `PAID` / `UNPAID` label; the "Lapse forecast" table lists policy number, grace end date and premium at risk, with an empty-state message "No policies at risk" when empty _(category: ui)_
   - Verify: open the page with the E9-S1 fixture data and assert row counts and cell texts; switch to a date with no at-risk policies and assert the empty-state text
3. [AC-20] Changing the "As of" date refetches with `?as_of=YYYY-MM-DD` and updates all cards and tables; a loading indicator is shown and an API error shows an inline alert with a "Retry" button _(category: ui)_
   - Verify: set the date to `2027-01-01` and assert a request with `as_of=2027-01-01`; stub a 500 response and assert the alert and "Retry" button; click "Retry" after restoring the stub and assert data renders
4. [—] The dashboard nav item and route are only available to the Admin role; the Customer and Underwriter demo users are shown a "Not authorised" page at `/admin/portfolio` _(category: security)_
   - Verify: switch the header role switcher to Customer and open `/admin/portfolio`; assert the text "Not authorised" and no dashboard cards; assert the nav has no "Portfolio" link for Customer and Underwriter
5. [AC-24] At 390 px the cards stack in one column and both tables render as stacked cards with no horizontal scroll; all controls are keyboard-reachable with visible focus and money/status are not conveyed by colour alone _(category: ui)_
   - Verify: set viewport 390×844 and assert `document.documentElement.scrollWidth <= 390`; tab through the page and assert each focused element has an accessible name; assert status cells contain the text `PAID`/`UNPAID`
