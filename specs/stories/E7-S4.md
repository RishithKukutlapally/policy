# E7-S4 — Renew API/UI + admin "run end-of-day"

- **ID:** E7-S4
- **Epic:** E7 — Renewal, lapse & payments
- **Layer:** UI
- **Group:** S4-D
- **Sprint:** 4
- **Depends on:** E7-S3, E5-S3
- **Traces:** AC-07, AC-17, AC-18, AC-22, NFR-04

## Description

Expose `GET /api/policies/{policy_number}/renewal` (renewal quote), `POST /api/policies/{policy_number}/payments`
(simulated payment), `POST /api/policies/{policy_number}/renew` (early renewal inside the window) and the
admin-only `POST /api/admin/end-of-day` (body `{as_of}`) in `src/api/routers/`. Build the customer
**Renew** screen (refreshed premium, due date, grace end, "Pay premium" action) and an admin **Run end-of-day**
control that shows the renewed/lapsed/failed counts.

## Acceptance Criteria

1. [AC-07] `GET /api/policies/MO-2026-000001/renewal` for the owning CUSTOMER returns 200 with `renewal_premium` (2-decimal string from the active rule version), `rule_version`, `due_date` and `grace_end_date` (due + 30 days); for a `CANCELLED` policy it returns 409 _(category: integration)_
   - Verify: GET as the owner and assert 200 and the four fields with `grace_end_date - due_date == 30 days`; GET for a CANCELLED policy and assert 409 with error code `INVALID_POLICY_STATE`
2. [AC-17] `POST /api/policies/MO-2026-000001/payments` with `{"amount": "15500.00"}` returns 201 and the payment id; `{"amount": "0.00"}` returns 422; the Renew screen's "Pay premium" button records the payment and then shows the badge `PAID` _(category: functional)_
   - Verify: POST valid and invalid amounts and assert 201 / 422; in Playwright as the Customer demo user open `/policies/MO-2026-000001/renew`, click "Pay premium" and assert the text `PAID` is visible
3. [AC-18] `POST /api/admin/end-of-day` with `{"as_of": "2027-01-15"}` as ADMIN returns 200 with `{renewed, lapsed, failed}` counts; calling it again with the same date returns `{"renewed": 0, "lapsed": 0, "failed": 0}` _(category: functional)_
   - Verify: seed due policies; POST twice with the same body; assert the first response has non-zero counts and the second is all zeros
4. [—] `POST /api/admin/end-of-day` returns 403 for `CUSTOMER` and `UNDERWRITER`, 401 without `X-Actor-Id`, and each ADMIN run writes one `AuditRecord` with the actor id, action `RUN_END_OF_DAY`, `as_of` and the counts _(category: security)_
   - Verify: POST as CUSTOMER and UNDERWRITER and assert 403; POST without headers and assert 401; POST as ADMIN `admin-001` and assert one new `audit_records` row with `actor_id = admin-001` and action `RUN_END_OF_DAY`
5. [AC-07] The admin "Run end-of-day" control (date picker defaulting to today, labelled button) displays the result counts, and a renewed policy then shows status `RENEWED` with a link to its new-term policy in Policy Detail _(category: ui)_
   - Verify: in Playwright as the Admin demo user choose `2027-01-15` and click "Run end-of-day"; assert the text `Renewed: 1`; switch to the Customer demo user, open the old policy and assert badge `RENEWED` and a link to the new policy number
6. [AC-07] `POST /api/policies/MO-2026-000001/renew` by the owner with the `business_date` setting fixed to `2027-02-15` (env `POLICYFORGE_BUSINESS_DATE`, read via `src/lib/clock.py::today()` — DEC-012) (inside the window opened `2027-01-29`) with the renewal premium paid returns 201 with the successor (new number, `previous_policy_number` `MO-2026-000001`, effective `2027-03-01`) and the old policy `RENEWED`; without the payment it returns 422 `RENEWAL_PREMIUM_UNPAID`, and with `business_date` `2026-12-01` it returns 409 `OUTSIDE_RENEWAL_WINDOW` _(category: integration)_
   - Verify: pay `15500.00` then POST renew and assert 201 and the successor fields; POST renew for an unpaid sibling policy and assert 422 with the detail code; restart with `POLICYFORGE_BUSINESS_DATE=2026-12-01`, POST renew and assert 409 `OUTSIDE_RENEWAL_WINDOW`
