## Description

Extend `python -m src.seed` (`backend/src/seed.py`) so `npm start` produces a demo-ready database: the three
v1 products, synthetic customers, quotes, applications run through the real underwriting and issuance services
(≥ 70 % `AUTO_BIND`, success metric M3), and sample policies across the lifecycle. Update the README with a
quick-start that gets a new developer from clone to a running UI with demo users.

## Acceptance Criteria

1. [AC-02] After `uv run python -m src.seed` on an empty database, `rule_set_versions` holds one `PUBLISHED` v1 row for each of `TERM_LIFE`, `MOTOR`, `HOUSEHOLD`, and running the seed a second time adds no rows (idempotent) _(category: functional)_
   - Verify: run the seed against a fresh SQLite file; query and assert 3 PUBLISHED rows with distinct products; run again and assert row counts in every table are unchanged
2. [AC-04] The seed submits at least 20 applications through the application/underwriting service (not direct inserts), and at least 70 % of them receive `AUTO_BIND`, with the remainder split between `MANUAL_REVIEW` and `DECLINE` (at least one of each) with reason codes like `MO-UW-001` _(category: functional)_
   - Verify: after seeding, query `underwriting_decisions`; assert total ≥ 20, `AUTO_BIND / total >= 0.70`, and ≥ 1 `MANUAL_REVIEW` and ≥ 1 `DECLINE` each with a non-empty reason code matching `^(TL|MO|HH)-UW-\d{3}$`
3. [AC-05] Sample policies are issued via the issuance service with numbers like `MO-2026-000001` and cover every lifecycle status: at least one each of `ACTIVE`, `ENDORSED`, `LAPSED`, `CANCELLED` and `RENEWED`, with matching transition, endorsement, payment and refund rows _(category: integration)_
   - Verify: query `policies` grouped by status and assert each of the 5 statuses has ≥ 1 row; assert every policy has ≥ 1 `policy_state_transitions` row, every new-business policy has its first-term `premium_payments` row and every CANCELLED policy has exactly 1 `refunds` row
4. [—] All seeded personal data is synthetic: every Aadhaar is 12 digits starting `9999`, every PAN matches `AAAAA\d{4}A`, names follow `Test Customer NN`, and the seed log output contains no raw Aadhaar or PAN _(category: security)_
   - Verify: query all applicant KYC fields and assert the patterns; capture stdout/stderr of the seed run and assert no match for `\b9999\d{8}\b` or `AAAAA\d{4}A`
5. [—] `README.md` has a "Quick start" section listing prerequisites (Python 3.12, uv, Node 20+), the single `npm start` command, the URLs `http://localhost:8000/health` and `http://localhost:3000`, and the three demo users (Customer / Underwriter / Admin) with their `X-Actor-Id` values _(category: integration)_
   - Verify: grep `README.md` for the heading "Quick start", `npm start`, both URLs and the three role names; on a clean clone run `npm start` and assert `/health` returns 200 and the UI loads
