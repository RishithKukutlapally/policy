# E1-S1 — Backend skeleton: settings, DB session, Alembic baseline, `/health`, `npm start`

- **ID:** E1-S1
- **Epic:** E1 — Platform foundation
- **Layer:** API
- **Group:** S1-A
- **Sprint:** 1
- **Depends on:** —
- **Traces:** AC-21, NFR-05, NFR-07

## Description

Create the runnable backbone every later story builds on: the FastAPI app `src.main:app`, typed settings in
`src/config/settings.py`, a SQLAlchemy 2 session factory over SQLite, an Alembic baseline revision and the
un-prefixed `GET /health` endpoint. A single root `npm start` installs dependencies, migrates the database
and starts the API on :8000 and the UI on :3000, so the evaluator can boot the app with one command.

## Acceptance Criteria

1. [AC-21] `GET /health` returns HTTP 200 with JSON body `{"status": "ok"}` and is the only route not under the `/api` prefix _(category: functional)_
   - Verify: call `GET /health` with the FastAPI TestClient; assert status 200 and body `{"status": "ok"}`; list `app.routes` and assert every other route path starts with `/api`
2. [AC-21] After `npm start` (or `uv run uvicorn src.main:app --port 8000`) the first `GET http://localhost:8000/health` answering 200 arrives within 1 s of the process reporting startup complete _(category: performance)_
   - Verify: start the backend process and record the "Application startup complete" timestamp; poll `/health` every 50 ms; assert first 200 is received ≤ 1.0 s later
3. [—] `src/config/settings.py` exposes a typed `Settings` object read from environment variables with defaults `DATABASE_URL=sqlite:///./policyforge.db`, `API_PORT=8000`, `UI_PORT=3000`, `RENEWAL_WINDOW_DAYS=30` (`docs/conventions.md` → Settings); overriding `DATABASE_URL` in env changes the engine URL _(category: functional)_
   - Verify: instantiate `Settings()` with a clean env and assert the four defaults; set `DATABASE_URL=sqlite:///./tmp-test.db` and assert `Settings().database_url` equals it; assert mypy strict passes on the module
4. [—] `alembic upgrade head` on an empty SQLite file succeeds and leaves exactly one head revision; a second `alembic upgrade head` is a no-op _(category: integration)_
   - Verify: run `uv run alembic upgrade head` against a temp DB; assert `alembic heads` prints exactly one revision; run upgrade again and assert exit code 0 with no new revision applied
5. [—] Alembic migrations are append-only: the architecture test fails if an existing file in `backend/migrations/versions/` is modified or deleted relative to `git merge-base HEAD main`, and passes when only new revision files are added _(category: security)_
   - Verify: run the migration-immutability test on a clean branch and assert pass; edit the baseline revision in a temp worktree and assert the test fails naming the file; add a new revision file and assert the test passes
6. [—] Root `npm start` runs, in order, backend install (`uv sync`), `alembic upgrade head`, the API on port 8000 and the Vite UI on port 3000; `http://localhost:3000` returns HTTP 200 _(category: integration)_
   - Verify: run `npm start` on a fresh checkout; wait for both ports to listen; assert `GET :8000/health` is 200 and `GET :3000/` is 200 with an HTML document
