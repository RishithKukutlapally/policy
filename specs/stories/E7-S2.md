# E7-S2 — Simulated premium payments

- **ID:** E7-S2
- **Epic:** E7 — Renewal, lapse & payments
- **Layer:** Service
- **Group:** S4-B
- **Sprint:** 4
- **Depends on:** E5-S2, E7-S1
- **Traces:** AC-17, NFR-02, NFR-01

## Description

Implement `src/service/premium_payment_service.py`, a "mark premium paid" simulation (no real gateway). Each
payment is an append-only `PremiumPayment` row (table `premium_payments`: policy id, term due date, amount,
paid_at, actor) that the renewal/lapse logic reads to decide whether the renewal premium for a due date is
paid, so a paid policy never lapses.

## Acceptance Criteria

1. [AC-17] `record_payment(policy_number="MO-2026-000001", amount=Decimal("15500.00"), actor_id)` for a policy whose renewal due date is `2027-03-01` and whose renewal quote on MOTOR v1 is `15500.00` (vehicle still in the 0–5 band) appends one `PremiumPayment` with `due_date = 2027-03-01`, `amount = Decimal("15500.00")`, `rule_version = 1` and the actor id _(category: functional)_
   - Verify: call `record_payment`; assert one row in `premium_payments` with the listed values; assert `amount` is a `Decimal` with exponent `-2`
2. [AC-17] `is_paid(policy, due_date)` is `True` only once the full renewal premium for that due date is recorded; an amount different from the quoted premium (`10000.00` against `15500.00`) is rejected with `AMOUNT_MISMATCH`, and a second payment for the same due date raises `PremiumAlreadyPaidError` (API 409 `PREMIUM_ALREADY_PAID`) _(category: functional)_
   - Verify: record `10000.00` and assert the mismatch error and `is_paid` is `False`; record `15500.00` and assert `True`; record `15500.00` again and assert `PremiumAlreadyPaidError`; assert a payment for a different due date does not count
3. [AC-17] A policy with the renewal premium paid is never lapsed: with payment recorded and `as_of = 2027-04-01` (past grace end `2027-03-31`), the lapse decision for that policy is `RENEW`, not `LAPSE` _(category: integration)_
   - Verify: record full payment for due date `2027-03-01`; evaluate the E7-S1 `renewal_action` using `is_paid`; assert `RENEW`; repeat without payment and assert `LAPSE`
4. [—] `PremiumPaymentRepository` exposes only `add(...)` and reads; a payment cannot be edited or deleted, and a correction is a new row _(category: security)_
   - Verify: assert the repository has no attribute containing `update` or `delete`; run `backend/tests/architecture/` and the `append-only-repository-check` hook self-test and assert both pass
5. [—] Payments are rejected with a typed validation error for amount `<= 0.00` or with more than 2 decimal places, with `OutsideRenewalWindowError` (409 `OUTSIDE_RENEWAL_WINDOW`) before `expiry_date − renewal_window_days`, and with `InvalidPolicyStateException` for policies in `LAPSED`, `CANCELLED` or `RENEWED`; nothing is persisted _(category: functional)_
   - Verify: call `record_payment` with `0.00`, `-1.00`, `"100.005"`, on `2026-12-01` (before the window opens `2027-01-29`) and for a CANCELLED policy; assert an error each time; assert the `premium_payments` row count is unchanged
