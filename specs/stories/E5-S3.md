# E5-S3 — Policy views API + My Policies / Policy Detail UI

- **ID:** E5-S3
- **Epic:** E5 — Policy issuance & lifecycle
- **Layer:** UI
- **Group:** S3-C
- **Sprint:** 3
- **Depends on:** E5-S2, E1-S5
- **Traces:** AC-15, AC-05, AC-22, AC-24

## Description

Expose policies through `src/api/routers/policies.py` (`POST /api/applications/{application_id}/issue`,
`GET /api/policies`, `GET /api/policies/{policy_number}`) and build the customer **My Policies** list and
**Policy Detail** screens. A customer sees only their own policies with premium, next premium due date,
lifecycle status (text badge) and endorsement history; underwriters and admins may view any policy.

## Acceptance Criteria

1. [AC-15] `GET /api/policies` with `X-Actor-Role: CUSTOMER` and `X-Actor-Id: cust-001` returns 200 with only cust-001's policies, each with `policy_number`, `product`, `status`, `sum_insured` and `premium` as 2-decimal strings (e.g. `"15500.00"`), `effective_date`, `expiry_date` and `next_premium_due_date` (= `expiry_date` + 1 day, the renewal due date, e.g. `2027-03-01`; the first term was paid at issuance) _(category: functional)_
   - Verify: seed 2 policies for cust-001 and 1 for cust-002; call the endpoint as cust-001; assert 200, exactly 2 items, and the field values/formats listed
2. [AC-15] `GET /api/policies/{policy_number}` returns the policy plus `endorsements` (type, before/after values, premium delta, created_at; oldest first) and `transitions` (from, to, at); a CUSTOMER requesting another customer's policy gets 404 and an unknown number gets 404 _(category: security)_
   - Verify: seed a policy with 2 endorsements and 3 transitions; GET it as the owner and assert 200 with 2 endorsements and 3 transitions in order; GET it as cust-002 and assert 404 `NOT_FOUND`; GET `MO-2026-999999` and assert 404
3. [AC-05] `POST /api/applications/{application_id}/issue` returns 201 with the new `policy_number` for an `AUTO_BIND` application, 409 `INVALID_APPLICATION_STATE` for any other application status, and 401 `UNAUTHENTICATED` without `X-Actor-Id` _(category: integration)_
   - Verify: POST for an AUTO_BIND application and assert 201 and body `policy_number` matching `^(TL|MO|HH)-\d{4}-\d{6}$`; repeat the POST and assert 409; POST without headers and assert 401
4. [AC-15] The My Policies screen lists each policy with policy number, product, premium formatted `en-IN` (`₹15,500.00`), next premium due date and a text status badge (`ACTIVE`, `ENDORSED`, …); selecting a row opens Policy Detail showing the endorsement history table and lifecycle timeline _(category: ui)_
   - Verify: with Playwright as the Customer demo user open `/policies`; assert the row text contains `MO-2026-000001`, `₹15,500.00` and `ACTIVE`; click the row and assert the detail page shows headings "Endorsement history" and "Lifecycle"
5. [AC-24] At 390 px the policy table renders as stacked cards and the side nav collapses; all interactive elements have accessible names and are reachable by keyboard _(category: ui)_
   - Verify: set viewport 390×844 and open `/policies`; assert no horizontal scrollbar and each policy is a card; tab through the page and assert every focused element has an accessible name
