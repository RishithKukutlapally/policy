# E6-S3 — Endorsement API + Endorse UI

- **ID:** E6-S3
- **Epic:** E6 — Endorsements
- **Layer:** UI
- **Group:** S3-D
- **Sprint:** 3
- **Depends on:** E6-S2, E5-S3
- **Traces:** AC-06, AC-16, AC-10, AC-22, AC-24

## Description

Expose `POST /api/policies/{policy_number}/endorsements` in `src/api/routers/endorsements.py` and build the
customer **Endorse** screen reached from Policy Detail. The form offers only the endorsement types allowed by
the policy's rule set, previews the premium delta for a sum-insured change via
`POST /api/policies/{policy_number}/endorsements?preview=true` (200, nothing persisted), and on success returns to
Policy Detail where the new endorsement appears in the history.

## Acceptance Criteria

1. [AC-06] `POST /api/policies/MO-2026-000001/endorsements` by the owning CUSTOMER with `{"type": "CHANGE_ADDRESS", "address": "2 Sample Road, Testville"}` returns 201 with the endorsement id, `premium_delta: "0.00"` and policy status `ENDORSED` _(category: integration)_
   - Verify: POST with `X-Actor-Role: CUSTOMER` and the owner's `X-Actor-Id`; assert 201 and the body fields; GET the policy and assert the endorsement appears in `endorsements`
2. [AC-16] Validation failures return 422 `VALIDATION_ERROR` with `details` field errors: a type not in `allowed_types` (`{field: "type", code: "NOT_ALLOWED"}`), a sum insured outside `100000.00`–`5000000.00` for MOTOR v1, or a missing `nominee_name`; nothing is persisted _(category: functional)_
   - Verify: POST each invalid payload; assert 422 and an `error.details` entry naming the offending field; assert the `endorsements` row count is unchanged
3. [AC-10] Endorsing a `CANCELLED`, `LAPSED` or `RENEWED` policy returns 409 with error code `INVALID_POLICY_STATE`; a CUSTOMER endorsing another customer's policy gets 404 and a request without `X-Actor-Id` gets 401 _(category: security)_
   - Verify: POST against a CANCELLED policy and assert 409 and the error code; POST as cust-002 on cust-001's policy and assert 404 `NOT_FOUND`; POST without actor headers and assert 401
4. [AC-16] The Endorse screen shows a type selector limited to the rule set's allowed types; with the `business_date` setting fixed to `2026-09-01` (env `POLICYFORGE_BUSINESS_DATE=2026-09-01`, read by every layer through `src/lib/clock.py::today()` — DEC-012), choosing `CHANGE_SUM_INSURED` for `MO-2026-000001` (premium `15500.00`, term `2026-03-01`–`2027-02-28`) and entering `600000.00` shows the preview formatted `en-IN` `+₹1,537.26` (= (18600.00 − 15500.00) × 181 / 365) before submission; inline errors are shown next to labelled fields on 422 _(category: ui)_
   - Verify: start the app with `POLICYFORGE_BUSINESS_DATE=2026-09-01` and assert `src.lib.clock.today()` returns that date; with Playwright as the Customer demo user open `/policies/MO-2026-000001/endorse`; assert the selector options equal the allowed types; enter `600000.00` and assert the preview text `+₹1,537.26` and a request with `preview=true`; enter `99999` and submit, assert an inline error attached to the "Sum insured" field
5. [AC-24] After a successful submission the user lands on Policy Detail with a confirmation message and the new row in the endorsement history; the form is usable at 390 px with keyboard only _(category: ui)_
   - Verify: submit a valid CHANGE_ADDRESS; assert URL `/policies/MO-2026-000001`, status badge `ENDORSED` and a new history row; repeat at viewport 390×844 using only keyboard input and assert the same outcome
