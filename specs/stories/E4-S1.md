# E4-S1 — Application validator + underwriting decision rules

- **ID:** E4-S1
- **Epic:** E4 — Application & underwriting
- **Layer:** Domain
- **Group:** S2-A
- **Sprint:** 2
- **Depends on:** E2-S1
- **Traces:** AC-03, AC-04

## Description

Two pure domain modules. `src/domain/application_validator.py` validates the KYC stub (full name, date of birth,
synthetic Aadhaar, PAN, address; plus a health declaration for TERM_LIFE) and risk inputs against the product's
`RuleSet` eligibility, returning field errors. `src/domain/underwriting_rules.py` evaluates the rule set's
`underwriting.rules` and returns an `UnderwritingOutcome(decision, reason_codes, rule_version)` with precedence
DECLINE > MANUAL_REVIEW > AUTO_BIND and all matching reason codes sorted ascending.

## Acceptance Criteria

1. [AC-03] A valid MOTOR application (full_name `Test Customer 01`, date_of_birth `1996-04-01`, aadhaar `999900000001`, pan `AAAAA0001A`, address `1 Sample Street, Testville`, owner_age 30, sum_insured `500000.00`, vehicle_age_years 3) returns an empty error list; KYC stub status is `VERIFIED` _(category: functional)_
   - Verify: load `motor/v1.json`; call `validate_application(rule_set, kyc, risk)`; assert `errors == []` and `kyc_status == "VERIFIED"`
2. [AC-03] Invalid KYC/risk inputs return field errors: aadhaar `12345` → `{field: "kyc.aadhaar", code: "INVALID_FORMAT"}` (must be 12 digits); pan `ABC123` → `{field: "kyc.pan", code: "INVALID_FORMAT"}` (pattern `^[A-Z]{5}[0-9]{4}[A-Z]$`); MOTOR owner_age 76 → `{field: "owner_age", code: "OUT_OF_RANGE"}`; TERM_LIFE without `health_declaration` → `{field: "health_declaration", code: "REQUIRED"}` _(category: functional)_
   - Verify: call `validate_application` with each defective input; assert the exact field/code pair is in the result; assert valid fields produce no error
3. [AC-04] MOTOR outcomes on v1: vehicle_age_years 3, sum_insured 500000 → `AUTO_BIND`, `()`; vehicle_age_years 12 → `MANUAL_REVIEW`, `("MO-UW-002",)`; vehicle_age_years 16, sum_insured 3000000 → `DECLINE`, `("MO-UW-001", "MO-UW-002", "MO-UW-003")`; each outcome has `rule_version == 1` _(category: functional)_
   - Verify: call `evaluate_underwriting(motor_v1, risk)` for the three inputs; assert decision, the exact reason-code tuple and rule_version
4. [AC-04] TERM_LIFE and HOUSEHOLD outcomes on v1: TERM_LIFE age 50, term_years 30 (`age_at_term_end` 80 > 75) → `DECLINE` `("TL-UW-001",)`; TERM_LIFE age 35, term 20, has_pre_existing_condition true → `MANUAL_REVIEW` `("TL-UW-003",)`; HOUSEHOLD `THATCH` → `DECLINE` `("HH-UW-001",)`; HOUSEHOLD in_flood_zone true, sum_insured 6000000 → `MANUAL_REVIEW` `("HH-UW-002",)`; HOUSEHOLD `BRICK`, no flood zone → `AUTO_BIND` `()` _(category: functional)_
   - Verify: evaluate each input against its v1 rule set; assert decision and reason-code tuple
5. [AC-04] Reason codes come only from the evaluated rule set: every returned code is a key of `rule_set.underwriting.reason_codes`, and a rule set whose rule references an undefined code raises `UnknownReasonCodeError` _(category: functional)_
   - Verify: for all outcomes above assert codes ⊆ `reason_codes` keys; construct a `RuleSet` with a rule code `MO-UW-999` not in `reason_codes` and assert `UnknownReasonCodeError` on evaluation
6. [—] Both modules are pure: no logging, I/O or clock (age is passed in, not derived from `date.today()`), and error objects never contain the raw Aadhaar/PAN value _(category: security)_
   - Verify: run `test_domain_purity` and assert pass; validate an input with an invalid 11-digit aadhaar `99990000000` and assert the error's message/str does not contain it
