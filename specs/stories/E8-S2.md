# E8-S2 — Cancellation service + append-only `Refund`

- **ID:** E8-S2
- **Epic:** E8 — Cancellation & refunds
- **Layer:** Service
- **Group:** S4-B
- **Sprint:** 4
- **Depends on:** E8-S1, E5-S2
- **Traces:** AC-08, AC-10, NFR-02

## Description

Implement `src/service/cancellation_service.py` with `preview_refund(policy_number, cancellation_date)` and
`cancel(policy_number, cancellation_date, reason, actor_id)`. Cancelling computes the refund with the E8-S1
rules from the policy's recorded rule version and, in one transaction, appends a `Refund` row (table
`refunds`), moves the policy to `CANCELLED` via the state machine and appends a `PolicyStateTransition`.

## Acceptance Criteria

1. [AC-08] Cancelling `TL-2026-000001` (E8-S1 golden policy: premium `12000.00` paid at issuance, `2026-01-01`–`2026-12-31`, status `ACTIVE`) on `2026-04-01` sets status `CANCELLED`, appends one `Refund` with `amount = Decimal("8791.10")`, `refund_type = PRO_RATA`, `admin_fee = Decimal("250.00")`, `unused_days = 275`, the rule version and the actor id, and appends one `ACTIVE → CANCELLED` transition _(category: functional)_
   - Verify: call `cancel(...)`; assert policy status, the single refund row's fields and the transition row; assert `refund.amount` is a `Decimal`
2. [AC-08] `preview_refund` returns the same amount and breakdown as `cancel` for the same date but writes nothing _(category: functional)_
   - Verify: call `preview_refund` for `2026-04-01` and assert amount `Decimal("8791.10")`; assert `refunds` and `policy_state_transitions` counts unchanged and policy still `ACTIVE`; call `cancel` and assert the persisted amount equals the preview
3. [AC-10] Cancelling a policy already `CANCELLED`, `LAPSED` or `RENEWED` raises `InvalidPolicyStateException` (API 409 `INVALID_POLICY_STATE`) and writes no second `Refund`; an `ENDORSED` policy can be cancelled _(category: functional)_
   - Verify: cancel the same policy twice and assert the second call raises and `refunds` has exactly 1 row for it; cancel an ENDORSED policy and assert success
4. [AC-08] Atomicity: if the transition insert fails, no refund row persists and the policy status is unchanged _(category: integration)_
   - Verify: patch `PolicyStateTransitionRepository.add` to raise; call `cancel` and assert the exception; assert no refund row and status still `ACTIVE`
5. [—] `RefundRepository` exposes only `add(...)` and reads; refunds are never updated or deleted _(category: security)_
   - Verify: assert the repository has no attribute containing `update` or `delete`; run `backend/tests/architecture/` and the `append-only-repository-check` hook self-test and assert both pass
