# E2-S2 — Rule loader, `RuleSetVersion` model/repository, seed import

- **ID:** E2-S2
- **Epic:** E2 — Product catalog & rule versions
- **Layer:** Repository
- **Group:** S1-C
- **Sprint:** 1
- **Depends on:** E1-S1, E1-S3, E2-S1
- **Traces:** AC-02, NFR-02, NFR-05

## Description

Parse rule files into `RuleSet` objects via `src/config/rule_loader.py` (schema-validated), persist versions in
the append-only `rule_set_versions` table through `rule_set_version_repository.py`, and import the three
published v1 files at startup/seed. Because the table is append-only, a status change (DRAFT → PUBLISHED) is
recorded as a new row for the same `(product, version)`; each row carries a `revision` (DEC-013) and the
current state of a version is its row with the highest `revision`.

## Acceptance Criteria

1. [AC-02] `rule_loader.load_rule_file(path)` returns a `RuleSet` for each of the three v1 files, and raises `RuleFileValidationError` listing the JSON path for a schema-invalid file (e.g. missing `premium.base_rate`) _(category: functional)_
   - Verify: load `term_life/v1.json`, `motor/v1.json`, `household/v1.json` and assert `rs.product` matches; load a temp file without `premium.base_rate`; assert `RuleFileValidationError` whose message contains `premium`
2. [AC-02] Alembic revision `0003_rule_set_versions` (added after `0002`, editing no earlier revision) creates `rule_set_versions` with columns `id`, `product`, `version`, `revision`, `status` (`DRAFT`|`PUBLISHED`), `content` (JSON), `content_sha256`, `actor_id`, `created_at`, a unique constraint on `(product, version, revision)` and a partial unique index on `(product, version)` where `status = 'PUBLISHED'` (DEC-013) _(category: integration)_
   - Verify: run `alembic upgrade head` on a temp DB and assert a single head; inspect the columns, the `(product, version, revision)` unique constraint and the partial unique index predicate; assert earlier revision files are byte-identical to `main`
3. [AC-02] A DRAFT replace appends a new row with `revision + 1` for the same `(product, version)` while publishing appends a PUBLISHED row; a second PUBLISHED row for the same `(product, version)` is rejected by the partial unique index (DEC-009, DEC-013) _(category: integration)_
   - Verify: append MOTOR v2 DRAFT `revision` 1, then a replacement DRAFT and assert `revision == 2` with both rows present; append a PUBLISHED row for MOTOR v2 and assert it succeeds; attempt a second PUBLISHED row for MOTOR v2 and assert `IntegrityError`
4. [AC-02] Seed import `import_published_rule_files()` inserts one PUBLISHED row per v1 file (3 rows) with `content_sha256` equal to the hash in `PUBLISHED.lock`; running it a second time inserts 0 rows _(category: integration)_
   - Verify: run the import on an empty DB and count rows (3); compare each `content_sha256` to the lock file; run again and assert still 3 rows
5. [—] The import aborts with `PublishedRuleFileTamperedError` and inserts nothing if any file's SHA-256 differs from its `PUBLISHED.lock` line _(category: security)_
   - Verify: copy `backend/policy_rules` to a temp dir and change one character in `household/v1.json`; run the import against the temp dir; assert the error names `household/v1.json` and the table is empty
6. [—] `RuleSetVersionRepository` is append-only: public methods are `add`, `latest_status(product, version)`, `list_for_product(product)` and `active_for_product(product)` only; `active_for_product` returns the highest version whose latest status is PUBLISHED, or `None` _(category: functional)_
   - Verify: introspect public methods and assert the exact set; insert MOTOR v1 PUBLISHED and v2 DRAFT; assert `active_for_product(MOTOR).version == 1`; append v2 PUBLISHED and assert it becomes 2
