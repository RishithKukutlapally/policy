# E6-S1 — Endorsement rules: types, eligibility, premium delta

- **ID:** E6-S1
- **Epic:** E6 — Endorsements
- **Layer:** Domain
- **Group:** S3-B
- **Sprint:** 3
- **Depends on:** E3-S1, E5-S1
- **Traces:** AC-16, NFR-01

## Description

Implement pure endorsement rules in `src/domain/endorsement_rules.py`: validate an endorsement request
(`CHANGE_ADDRESS`, `ADD_NOMINEE`, `CHANGE_SUM_INSURED`) against the policy's rule set and compute the
premium delta for a sum-insured change using the E3-S1 premium calculator. The delta is pro-rated over the
unused days of the current term and quantized to 0.01 `ROUND_HALF_UP`; no float is used anywhere.

## Acceptance Criteria

1. [AC-16] An endorsement type not listed in the rule set's `endorsement.allowed_types` is rejected with a typed validation error naming the type and the product; each of `CHANGE_ADDRESS`, `ADD_NOMINEE`, `CHANGE_SUM_INSURED` is accepted when listed _(category: functional)_
   - Verify: build a `RuleSet` fixture whose `allowed_types` is `["CHANGE_ADDRESS"]`; assert `ADD_NOMINEE` raises the error and its message contains `ADD_NOMINEE`; assert all three types validate against the full v1 rule set
2. [AC-16] `CHANGE_SUM_INSURED` outside the rule set's `eligibility.min_sum_insured`/`max_sum_insured` (MOTOR v1: `100000.00`–`5000000.00`) is rejected, as is a new value equal to the current sum insured; payload fields are validated (`CHANGE_ADDRESS` needs non-empty `address`, `ADD_NOMINEE` needs `nominee_name` and `relationship`) _(category: functional)_
   - Verify: assert `99999.99` and `5000000.01` are rejected and `100000.00` and `5000000.00` are accepted; assert an unchanged sum insured is rejected; assert missing `address` / `nominee_name` each produce a field-level error
3. [AC-16] For `CHANGE_SUM_INSURED`, `premium_delta = (new_annual_premium − current_premium) × unused_days / term_days`, quantized to 0.01 `ROUND_HALF_UP`: TERM_LIFE v1 policy (age 25, term_years 10, non-smoker) with current premium `12000.00` (sum insured `8000000.00`), recomputed premium `15000.00` (sum insured `10000000.00`), 182 unused of 365 days → delta `(15000.00 − 12000.00) × 182 / 365` = `Decimal("1495.89")`; a decrease yields a negative delta _(category: functional)_
   - Verify: call `premium_delta(...)` with those inputs and assert `== Decimal("1495.89")`; swap current/new premiums and assert `== Decimal("-1495.89")`; assert the result is a `Decimal` with exponent `-2`
4. [—] The recomputed annual premium comes from the E3-S1 premium calculator using the policy's recorded rule version, and `CHANGE_ADDRESS` / `ADD_NOMINEE` always return `premium_delta == Decimal("0.00")` _(category: functional)_
   - Verify: assert the new annual premium equals `calculate_premium(rule_set_vN, updated_inputs)` for the same version; assert delta `0.00` for the two non-monetary types; run hook `premium-precision-check` on the module and assert no `float` usage is reported
5. [—] Endorsement is only eligible for policies in `ACTIVE` or `ENDORSED`; for `LAPSED`, `CANCELLED` or `RENEWED` the rules delegate to the E5-S1 state machine and `InvalidPolicyStateException` is raised _(category: functional)_
   - Verify: parametrise over the 5 `PolicyStatus` values; assert `ACTIVE` and `ENDORSED` pass; assert the 3 terminal statuses raise `InvalidPolicyStateException`
