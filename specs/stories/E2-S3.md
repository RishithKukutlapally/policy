# E2-S3 — Catalog service: list, active version, create draft, publish

- **ID:** E2-S3
- **Epic:** E2 — Product catalog & rule versions
- **Layer:** Service
- **Group:** S1-D
- **Sprint:** 1
- **Depends on:** E2-S2, E1-S3
- **Traces:** AC-11, NFR-02, NFR-04

## Description

`src/service/catalog_service.py` lets admins change rates and rules with zero code changes: list products with
their active version, list a product's versions, create a DRAFT version from a rule-set JSON body, and publish
it. Published versions are immutable and exactly one version per product is active (the highest PUBLISHED
version). Every create/publish is audited with the admin's actor id.

## Acceptance Criteria

1. [AC-11] `list_products()` returns exactly three entries (`TERM_LIFE`, `MOTOR`, `HOUSEHOLD`) each with `active_version == 1` after seed import _(category: functional)_
   - Verify: seed an empty DB with the v1 import; call `list_products()`; assert three products in that order and each `active_version` is 1
2. [AC-11] `create_draft(actor, MOTOR, rule_json)` with a schema-valid body stores a DRAFT row with `version = max existing version + 1` (2 for MOTOR), leaves the active version at 1, and writes an `audit_records` row `action="RULE_VERSION_DRAFT_CREATED"` with the admin's `actor_id`; a schema-invalid body raises `RuleFileValidationError` and stores nothing; a second `create_draft` while v2 is still DRAFT raises `DraftAlreadyOpenError` (API 409 `DRAFT_ALREADY_OPEN`) _(category: functional)_
   - Verify: call `create_draft` with a copy of `motor/v1.json` changed to base_rate `"0.0320"`; assert the new row is v2 DRAFT and `active_for_product(MOTOR).version == 1`; assert the audit row; call with base_rate numeric `0.032` and assert error and unchanged row count; call `create_draft` again and assert `DraftAlreadyOpenError`
3. [AC-11] `publish(actor, MOTOR, 2)` appends a PUBLISHED row for v2, after which MOTOR's active version is 2 and exactly one version is reported active for MOTOR; an `audit_records` row `action="RULE_VERSION_PUBLISHED"` is written _(category: functional)_
   - Verify: create a MOTOR v2 draft then publish; assert `active_for_product(MOTOR).version == 2`; assert `list_versions(MOTOR)` marks only v2 as `is_active`; assert the audit row with actor id
4. [AC-11] Published versions are immutable: publishing an already-PUBLISHED version raises `VersionAlreadyPublishedError` (API 409 `VERSION_IMMUTABLE`), and the service offers no operation to edit the content of a PUBLISHED version; the stored `content_sha256` of v1 is unchanged after v2 is published _(category: security)_
   - Verify: call `publish(actor, MOTOR, 1)` and assert `VersionAlreadyPublishedError`; assert the service's public API has no `update`/`edit` method; compare v1 `content_sha256` before and after publishing v2
5. [AC-11] A draft whose `product` field disagrees with the target product (e.g. `"product": "HOUSEHOLD"` posted for MOTOR) raises `RuleFileValidationError`, and publishing a non-existent version (MOTOR v9) raises `RuleVersionNotFoundError` _(category: functional)_
   - Verify: call `create_draft(actor, MOTOR, household_json)` and assert the error; call `publish(actor, MOTOR, 9)` and assert `RuleVersionNotFoundError`; assert no rows or audit records were written
6. [AC-11] `replace_draft(actor, MOTOR, 2, rule_json)` (DEC-009, API `PUT /api/products/MOTOR/versions/2`) appends a new DRAFT row for the same version with the new body and writes an `audit_records` row `action="RULE_VERSION_DRAFT_REPLACED"`; calling it for a PUBLISHED version raises `VersionAlreadyPublishedError` (API 409 `VERSION_IMMUTABLE`) and stores nothing _(category: functional)_
   - Verify: create a MOTOR v2 draft then call `replace_draft` with base_rate `"0.0330"`; assert a new row exists, the previous row is unchanged and `list_versions(MOTOR)` reports v2 DRAFT with base_rate `"0.0330"`; assert the audit row with actor id; call `replace_draft(actor, MOTOR, 1, ...)` and assert `VersionAlreadyPublishedError` with unchanged row count
